# DevOps Career & Behavioral Round — Hands-On Lab

Nine drills that turn behavioral-round answers into real experience. Each exercise gives you a goal, the steps, what you should see, and why it matters in the interview.

---

## Exercise 1: Write your 60-second "Tell me about yourself"

**Goal:** A present–past–future intro you can say out loud without notes.

**Steps:**

```bash
# Draft it in three lines, then time yourself reading it aloud:
# Present — who you are now (one sentence)
# Past — how you got here (one sentence)
# Future — why this role is next (one sentence)
# Target: 45–60 seconds. Cut anything that takes it past 75.
```

**Expected output:** A timed intro under 75 seconds that sounds like you talking, not reading a resume.

**Why it matters:** This is the Q1 starting point — the first answer sets the tone for the whole round.

## Exercise 2: Build your STAR story bank

**Goal:** Five stories, each mapped to the questions they answer.

**Steps:**

```bash
# For each story, write four short lines:
# S — the situation in one sentence
# T — your role, not the team's
# A — the steps you took, in order
# R — the result, with a number, plus the guardrail you added
# Pick: an outage, a disagreement, a project win, a mistake, a deadline crunch.
```

**Expected output:** Five STAR stories you can retell in under two minutes each, with the result quantified.

**Why it matters:** This is Q4 and Q6 made concrete — behavioral rounds reward prepared stories, not improvised ones.

---

## Exercise 3: Rehearse your outage story with a timer

**Goal:** An incident story that lands in under two minutes.

**Steps:**

```bash
# Tell your outage story aloud, timed. Then cut it:
# - Drop any detail that doesn't change the outcome
# - End on the guardrail, not on the fix
# - Record yourself once and listen for filler words
```

**Expected output:** A two-minute story where the fix takes 30 seconds and the guardrail gets the last word.

**Why it matters:** This is Q4 — interviewers remember the fix plus the guardrail, and a story that rambles loses both.

## Exercise 4: Rewrite three resume bullets with numbers

**Goal:** Resume bullets that prove impact, not list tools.

**Steps:**

```bash
# Take three bullets that say "worked on X" and rewrite each as:
# Action verb + what you built + measurable result
# Example: "Built CI/CD pipeline" -> "Automated deploys with GitHub
# Actions + ArgoCD, cutting release time from 1 hour to 10 minutes"
# If you don't know the number, go measure it before the interview.
```

**Expected output:** Three bullets with a verb, a result, and a number — ready to say out loud as Q3 evidence.

**Why it matters:** This is Q3 — "what you built" is forgettable, "what it changed, with a number" is the answer.

## Exercise 5: Write your 30-60-90 day plan for a real job posting

**Goal:** A plan tied to a real company's stack, not a generic template.

**Steps:**

```bash
# Pick a live DevOps job posting and read its stack and responsibilities.
# Write three short sections:
# 30 days — learn: architecture, pipeline, on-call, owners
# 60 days — contribute: own one flaky pipeline or missing alert
# 90 days — own: ship one reliability improvement, join on-call
# Name one specific thing per phase, tied to that posting.
```

**Expected output:** A one-page plan with a specific item per phase, clearly tied to the posting you read.

**Why it matters:** This is Q11 — learn first, contribute second, own third, with specifics that prove you read the posting.

## Exercise 6: Do a mock behavioral interview with a friend

**Goal:** Answers tested on a real listener, not just in your head.

**Steps:**

```bash
# Ask a friend to ask you Q1, Q4, Q6, and Q8 from this guide.
# Rules: no notes, two-minute limit per answer, and they interrupt
# with a follow-up question after each one ("What did you do next?").
# Afterwards, ask them which answer felt rehearsed and which felt real.
```

**Expected output:** Four timed answers plus honest feedback on which ones sounded natural and which sounded memorised.

**Why it matters:** Behavioral answers are spoken, not written — the mock is where you find the parts that only work on paper.

## Exercise 7: Draft your weakness story with the fix

**Goal:** A weakness answer with a real cost and a real habit fixing it.

**Steps:**

```bash
# Write three lines:
# 1. The weakness, in plain words (no humblebrags)
# 2. What it cost you once — a real moment
# 3. The concrete habit you're using to fix it, and how long you've kept it
# Say it aloud: if it sounds like an excuse, rewrite it.
```

**Expected output:** A 30-second answer that names a real weakness, a real cost, and a fix you can show.

**Why it matters:** This is Q8 — a weakness without a fix is a red flag, a weakness with a fix is growth.

## Exercise 8: Research salary bands for your next role

**Goal:** A number you can defend, not a guess, before anyone asks.

**Steps:**

```bash
# Check three sources (levels.fyi, Glassdoor, recent postings) for your
# role, years of experience, and city. Write down:
# - The range you found, and which source each number came from
# - Your walk-away number and your target number
# - One non-salary thing you'd trade for (remote days, learning budget)
```

**Expected output:** A written range with sources, plus a target and a walk-away number you decided before the negotiation.

**Why it matters:** Salary comes up in the same round as fit — deciding your number calmly now beats inventing it under pressure.

---

## Exercise 9: Prepare three questions to ask them

**Goal:** Questions that show you evaluated them, not just applied.

**Steps:**

```bash
# Write three questions you genuinely want answered, for example:
# - "What does on-call look like here — how often, and what happens after a bad night?"
# - "What's the last incident that changed how the team works?"
# - "What would success look like for this role in six months?"
# Avoid anything the job posting already answers.
```

**Expected output:** Three questions that reveal something about the team — and that you'd actually want to know before joining.

**Why it matters:** The questions you ask are the last impression of the round — they show whether you chose them or just applied everywhere.
